# jorqen — заметки для агентов

Личный репозиторий Matvey. **Две независимые части, не путай их:**

1. **Сайт-резюме** — статика на GitHub Pages: `resume/resume.yaml` → генератор → `en/`, `ru/`.
2. **`scout`** — сборщик вакансий: 47 модулей в `scripts/scout/`, обходит 28 площадок,
   складывает в локальную базу `.scout/`. Механика поиска работы. Суждение (кто подходит,
   какое письмо) — не здесь, а в скилле `jobs`.

Правка в одной части почти никогда не касается другой. Определись, где работаешь, до первой правки.

## Команды

```bash
# Сайт
scripts/build_resume_formats.sh          # resume.yaml → en/, ru/, PDF, DOCX, TXT
                                         # он же валидирует схему: не собралось — правка не сделана

# Scout — всегда через .venv
.venv/bin/python -m scripts.scout budget --days 3    # СМЕТА волны до запуска
.venv/bin/python -m scripts.scout wave --days 3      # весь конвейер + картина волны
.venv/bin/python -m scripts.scout shortlist          # дельта → строка на вакансию
.venv/bin/python -m scripts.scout auth status        # чем закрыт вход по площадкам
```

Полный список команд (≈45 штук) — таблица в
[scripts/scout/README.md](scripts/scout/README.md) в разделе «Команды».
**Не читай этот README целиком — он на 1200 строк.** Открывай нужный раздел по
оглавлению (`grep -n '^###' scripts/scout/README.md`) или ищи по команде.

**Тесты — восемь отдельных модулей, каждый запускается сам, pytest не нужен**
(его тут и нет — ядро на одной стандартной библиотеке, см. инвариант 3).
Список с назначением каждого — раздел «Тесты» того же README. Быстрая проверка
без сети:

```bash
for m in test_scout test_store test_coverage test_sources_web \
         test_sources_auth test_atsapi test_profile; do
  .venv/bin/python -m scripts.scout.$m || break
done
.venv/bin/python -m scripts.scout.test_e2e --offline   # шестой, обязательно с --offline
```

**`test_e2e` БЕЗ `--offline` делает живой обход всех площадок** — это десятки
минут, а не «тест завис». Флаг обязателен всегда, кроме случая, когда живой обход
и нужен. Есть ещё `--fast` — без браузерных площадок.

## Состояние и направление

- Сайт-резюме — **готов и стабилен**. Работа по нему — точечная: содержимое резюме,
  вёрстка, доступность. Новых подсистем не заводить.
- `scout` — **активно развивается**. Направление: больше площадок через официальные API
  вместо разбора вёрстки (уже сделано для hh.ru, Хабра, rabota.ru, levels.fyi),
  устойчивость к антибот-стенам, точность дедупа.
- Задач в GitHub Issues **нет** — очередь ведётся в переписке и в `.jobs/<дата>/`.
  Заводить issue не нужно, если человек не попросил.

**Новая подсистема — сначала разведка, потом код** (постоянное требование
владельца). Прежде чем писать: найди похожие open source-проекты, разбери их
архитектуру, стек и живость, предложи стек/архитектуру/границы MVP/порядок работ —
и **дождись подтверждения**. Скилл `/research` делает это по протоколу; если его
нет в окружении — правило всё равно действует. Точечные правки и багфиксы —
обычным порядком, без разведки.

### Чего НЕ делать

- Не заводить веб-панель, сервер или БД поверх `.scout/` — это локальный SQLite и так задумано.
- Не переносить суждение (отбор, тексты писем) в код: это зона модели, см. скилл `jobs`.
- Не добавлять площадки разбором вёрстки, если у площадки есть API.
- Не расширять `AGENTS.md`/`CLAUDE.md` пересказом того, что уже написано в
  `scripts/scout/README.md` — ссылайся.

## Делегирование субагентам

**Узкую задачу — дешёвой модели.** Разница в цене между тирами больше десяти раз, а на
ограниченных задачах с объективным признаком готовности качество почти не падает.

| Кому | Модель | Когда |
|---|---|---|
| `explorer` | Haiku | Ответ требует прочитать много или крупно. **Главный способ не тратить контекст на большие файлы:** он читает `sources.py` или `test_scout.py`, ты получаешь пять строк со ссылками `file:line`. |
| `worker` | Sonnet | Одна ограниченная правка от начала до конца, с зелёными тестами. |
| сам | — | Архитектура, выбор технологий, неоднозначные требования — всё, где «готово» решается суждением. |

- Делегируй **сформулированную** задачу с признаком готовности. «Разберись с площадкой» —
  не задача для субагента; «где разбирается вилка на hh» — задача.
- Не делегируй то, на что уже есть ответ в контексте: запуск субагента сам стоит токенов.
- Независимые задачи запускай **одним сообщением**, чтобы они шли параллельно.
- Субагентам **нельзя** `reveal`, `tg-mirror`, `tg-rollback`, `auth import` — платное
  и необратимое остаётся за человеком.
- Отчёт субагента — данные, а не истина. Про площадки особенно: они врут, и половина
  знаний лежит в `field-notes.md`, а не выводится из кода.

Определения — в `.claude/agents/`. Правило одинаково во всех трёх репозиториях; в
другом инструменте (Codex и пр.) применяй его же своим механизмом субагентов.

## Инварианты — не ломать

1. **Единый источник истины.** Значение живёт в одном месте:
   `resume/resume.yaml` — содержимое резюме, контакты, локализованные строки;
   файлы генерации — только то, что принадлежит сайту (аналитика, OG, медиа-варианты);
   `scripts/generate_resume_outputs.py` — только то, что принадлежит выгрузкам.
   **Сгенерированные файлы не править руками** — править источник и перегенерировать.
2. **EN и RU всегда совпадают** по смыслу и объёму, во всех форматах. Опыт
   сортируется по дате начала работы. DOCX и PDF выглядят одинаково.
3. **Ядро scout — только стандартная библиотека.** Он обязан подниматься на чужой
   машине и в облачной рутине без установки. Всё остальное — опционально, лениво
   импортируется из `.venv`. Не добавляй обязательных зависимостей в ядро.
4. **Репозиторий публичный.** `.auth/` (сессии площадок — предъявительский доступ к
   аккаунтам), `.scout/` (база), `.jobs/` — в `.gitignore` и там и остаются.
   Никогда не коммить куки, токены, тела писем, персональные данные из вакансий.
5. **`reveal` тратит платный лимит раскрытий** — единственная команда с необратимой
   ценой. Не вызывать «на всякий случай» и не ставить в автоматические прогоны.
6. **Синхронизации почты и площадок — только чтение.** `mail-sync`, `mail-read`,
   `tg-dm` не отмечают прочитанным и ничего не отправляют. Не добавлять отправку.
7. **Дедуп ошибается в сторону РАЗДЕЛЕНИЯ** (три слоя). Лучше показать дубль, чем
   потерять вакансию. Не «улучшать» до агрессивного слияния.

## Структура

- `resume/resume.yaml` — канонический источник резюме; `resume.schema.yaml` валидирует его.
- `scripts/generate_resume_outputs.py` — генератор страниц и выгрузок; `scripts/templates/` — Jinja2.
- `assets/` — стили, `app.js`, медиа (`light/`, `dark/`, генерируемые варианты в `generated/`).
- `index.html`, `en/`, `ru/` — **генерируемые**, в `.gitignore`; правишь источник, не их.
- `scripts/scout/` — сборщик. Точки входа: `cli.py` + `cliargs.py` (команды и их флаги),
  `sources.py` (площадки), `sources_web.py` / `sources_auth.py` (обход), `store.py` (база),
  `detail.py` + `clidetail.py` (выжимки), `salary.py` (разбор вилок),
  `webcommon.py` (общая механика обхода), `auth.py` + `authrefresh.py` (сессии и продление).
- `.claude/skills/jobs/` — скилл суждения: отбор, карточки, письма. Механику не дублирует.

## Где что записано (единый источник истины)

Прежде чем что-то выяснять заново — проверь, не записано ли это уже:

| Вопрос | Где ответ |
|---|---|
| Как работает команда scout, что значат статусы покрытия | `scripts/scout/README.md` |
| Что обходится на самом деле | реестр в `scripts/scout/sources*.py` — это правда |
| Чего ждать от площадки, что подключено, что требует захода человека | `.claude/skills/jobs/references/sources-setup.md` |
| Приёмы, ловушки, где площадка врёт — то, что не выводится из кода | `.claude/skills/jobs/references/field-notes.md` |
| Какие внешние API/проекты уже проверены и отвергнуты | `.claude/skills/jobs/references/oss-references.md` |
| Канон сопроводительного письма | `.claude/skills/jobs/references/letter-guide.md` |
| Содержимое резюме, контакты | `resume/resume.yaml` |

**Новый урок про площадку записывай в `field-notes.md`**, а не в код-комментарий и не
в отдельный файл. Отдельной «памяти агента» в этом репозитории нет намеренно —
эти четыре справочника её заменяют, второй системы не заводить.

## Большие файлы — не читать целиком (экономия контекста)

`scout` — большой код. Одно неосторожное чтение съедает прогон.

| Файл | Строк | Как заходить |
|---|---|---|
| `scripts/scout/test_scout.py` | ~3700 | `grep -n 'def test_'` → читать нужный тест |
| `scripts/scout/sources.py` | ~2200 | `grep -n 'def src_'` → нужная площадка |
| `scripts/scout/cli.py` | ~1975 | `grep -n 'def cmd_'` → нужная команда |
| `scripts/scout/test_sources_auth.py`, `test_sources_web.py`, `sources_web.py`, `sources_auth.py`, `test_store.py` | 1500–1850 | то же |
| `scripts/scout/README.md` | ~1300 строк | `grep -n '^###'` → нужный раздел |
| `.claude/skills/jobs/references/oss-references.md` | ~100 КБ | справочник, читать по `grep` |

Часть кода уже разъехалась по отдельным модулям — ищи там, прежде чем грепать
гиганты:

| Модуль | Что внутри |
|---|---|
| `salary.py` | разбор вилок |
| `webcommon.py` | общая механика обхода: стены, окно свежести, POST, вежливость |
| `sources_glassdoor.py` | единственная площадка за стеной |
| `reference_levels.py` | справочник зарплат, **НЕ** вакансии |
| `cliargs.py` | все подкоманды и флаги (сам разбор аргументов) |
| `clidetail.py` | команды `detail` и `enrich` |
| `authrefresh.py` | продление сессий и проба авторизации до прогона |
| `cardfiles.py` | раскладка карточек по каталогам и `lint-cards` |
| `wavedoc.py` | главный документ волны, слаг компании, индекс волн |
| `lintletter.py` | проверка письма на маркеры генератора |
| `testutil.py` | общее для тестов: подмена, подделки сети, даты |

Имена реэкспортируются из прежних модулей, поэтому старые импорты работают.

Правило общее: **файл больше ~1500 строк — сначала `grep -n`, потом `Read` с
`offset`/`limit`.** Дешевле на порядок и точнее.

## Стиль

Проект **русскоязычный**: документация, комментарии, сообщения коммитов — по-русски.
Содержимое резюме — двуязычное (EN/RU). Идентификаторы в коде — английские.
