### [job-board-aggregator](https://github.com/Feashliaa/job-board-aggregator)
**Наша задача:** 2.3 здоровье источников · ATS-first  
**Живость:** ЖИВОЙ, работает по расписанию: pushed_at 2026-08-04 (ежедневный прогон GitHub Actions), MIT. Данные вынесены в отдельный репозиторий Feashliaa/job-board-data, который force-push’ится каждым прогоном,

**Взять:** 1) ATS-first: публичные JSON-API Greenhouse/Lever/Ashby/Workable/BambooHR/iCIMS/Workday дают полное описание и прямую ссылку работодателя вообще без антибота — это и есть ответ на «найти прямой контакт вместо агрегатора». 2) Детект молча сломавшегося источника: ежедневный лог счётчиков по каждому источнику (append-only JSONL) + сравнение с недавним базовым уровнем, и при обвале/всплеске — автоматический алерт. **Не повторять:** Витрину копировать незачем: чанкованный gzip + Web Workers + GitHub Pages + force-push в отдельную репу — решение проблемы масштаба 1M вакансий, у вас её нет (SQLite закрывает всё). Дедуп «по идентичности» не решает вашу главную боль — одну вакансию с пяти площадок он не склеит. Статусы в localStorage — состояние, привязанное к браузеру: у вас правильнее в SQLite. Bus factor 1, весь конвейер завязан на бесплатные мин

### [huginn](https://github.com/huginn/huginn)
**Наша задача:** «лента из сайта без API» + дедуп как ОТДЕЛЬНЫЙ шаг конвейера  
**Живость:** ЖИВОЙ, и по коду тоже — проверено отдельно, потому что верхние коммиты бот-подобные («Lock file maintenance»): за полгода 46 коммитов по `app/`, среди них содержательные — «Fix duplicate events in RaindropBookmarksAgent», «Add Raindrop service and agents», «Improve agent search with type matching», «Raise MySQL sort_buffer_size for JSON columns». 49 750 звёзд, 695 открытых issue. **Не повторять:** Rails + MySQL + Delayed::Job + веб-UI ради персонального сборщика — на два порядка тяжелее задачи; 49k звёзд здесь означают «конструктор автоматизаций для всех», а не «сборщик вакансий». Готового источника вакансий нет ни одного. Дедуп по crc32 — это дедуп по ТОЧНОМУ совпадению ключа: перепечатку одной вакансии на пяти площадках он не склеит, за этим по-прежнему к SimHash/MinHash. Хранить окно виденного в поле `memory` одной записи — на объёмах больше нескольких тысяч это узкое место (у нас для этого есть таблица). И `Utils.stable_json` / `same_json?` — напоминание, что сравнение «одинаковости» объектов требует канонической сериализации: если делать похожее, порядок ключей фиксировать явно.

## LinkedIn: троттлинг гостевого поиска (разведка 07.08.2026)

**Наша задача:** есть ли готовое решение проблемы «пустой ответ вместо 429» и
как другие держат частоту у `jobs-guest/jobs/api/seeMoreJobPostings/search`.

**Итог: брать нечего, и это важный отрицательный результат.** Ни один из
разобранных выше проектов гостевым эндпоинтом не пользуется вовсе —
`py-linkedin-jobs-scraper` и `Auto_job_applier_linkedIn` водят Selenium по
видимой вёрстке (у второго проверено grep'ом: ни одного обращения к `voyager`,
`jobs-guest`, ни одного вызова requests). То есть наш путь уже дальше, чем у
самых звёздных решений, и заимствовать у них по этой задаче нечего.

**Что подтвердилось со стороны.** Публикации по теме independently называют ту
же границу, что стояла у нас в заметках: гостевой эндпоинт начинает отбиваться
примерно с десятой страницы с одного IP. Наш замер богаче: сотня страниц
проходит целиком, но отказ приходит **не кодом 429, а пустым телом в 26 байт с
кодом 200** — этого не пишет никто, и именно это молча обрезало нам выдачу.

**Стандартный ответ индустрии — ротация прокси — нами отвергнут.** Это не
вежливость к площадке и не оптимизация, а сокрытие источника запросов, то есть
обход ограничения переодеванием. В scout такого нет и не будет; вместо этого
частота держится честно (`sources.RateGate`), а пустой ответ переспрашивается.

**Правовой контекст (для протокола, не как совет юриста):** сбор публичных
данных без авторизации — предмет hiQ Labs v. LinkedIn, решённого в пользу
сборщика. Мы читаем ровно публичную выдачу без входа, ничего не подделывая.

**Полезное, что стоило проверки:** совет «листать шагом 25» к нашему эндпоинту
не относится — `count=25/50/100` и `start=25` дают ровно 10 карточек, параметр
