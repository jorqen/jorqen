# Местность: форматы, приёмы, известные поломки

Единственное место, где это записано. Всё проверено живыми вызовами в июле 2026;
где не проверено — сказано явно.

## Форматы ответов инструментов

Инструменты Telegram приходят с префиксом MCP-сервера, в котором есть UUID, и он
**меняется между сессиями**. Не хардкодь имя — подгружай через `ToolSearch`
(`{query: "telegram", max_results: 30}`).

`telegram-list-chats` (`filterType`: `private` | `group` | `channel`):

```
C RemoteGeekjob (-1001322005976) [20 unread]
C CryptoMarshall | Developer jobs (-1001962358063)
```

`C` — канал, `G` — группа, `P` — личный чат. Хвост `[N unread]` появляется только при
непрочитанных. Личные чаты и боты для скана вакансий не нужны.

`telegram-read-messages` — сообщения разделены пустой строкой, каждое начинается с `[#id]`:

```
[#1509] [2026-07-23T09:00:18.000Z] Название чата: текст сообщения
```

У него есть `minDate` / `maxDate` (unix-таймстемпы) — режим «с даты» лучше делать
серверной фильтрацией, а не вычиткой всего подряд.

**Архив отдаётся обычным `telegram-list-chats`, отдельного флага не нужно** — проверено
в июле 2026. Пройди три вызова, все три обязательны:

- `filterType: channel` — job-каналы (~19 шт.);
- `filterType: group` — **job-группы, и их легко пропустить**: 5 групп на 380 непрочитанных,
  включая первоисточник вакансий, которые в каналах появляются перепечаткой. Один заход
  без `group` — и теряется целый пласт;
- `filterType: private` — там боты с пометкой `[bot]`: getmatch, Хабр Карьера, hh.ru,
  Runello. Полноценный источник: адресные вакансии с открытыми вилками.

`telegram-get-chat-folders` по-прежнему не нужен (и падал раньше с `Connection closed`).

**Группы устроены иначе, чем каналы: половина сообщений — резюме соискателей, а не
вакансии.** В `<HOT IT JOBS>` это 26 из 48, в `CV & JOB by HR Breakfast` — 41 из 107,
в `CY iT HR` — почти всё. Отсеиваются по тегам `#резюме` / `#cv` / `#ищу_работу` и по
форме «Должность: … Опыт: … TG @…». Не считай их вакансиями и не трать на них ресёрч.
Зато вакансии в группах публикуют **живые рекрутёры с открытым @username** — по приоритету
контакта это лучше, чем каналы с ботами-перепечатками.

**Большие каналы не влезают в ответ.** `telegram-read-messages` на 47 сообщений отдал
85K символов и вместо результата — путь к файлу с полной выгрузкой. Это не ошибка и не
потеря: файл полный. Дальше по нему удобнее `grep -n '^\[#'` (индекс всех сообщений) и
`sed -n 'X,Yp'` по нужным диапазонам, чем читать целиком.

`telegram-get-message-buttons`:

```
Markup: ReplyInlineMarkup
  [0.0] KeyboardButtonUrl: Подробнее url=https://t.me/RunelloBot/runello?startapp=eyJvcmRlci...
  [0.1] KeyboardButtonUrl: Откликнуться url=https://t.me/RunelloBot/runello?startapp=eyJvcmRlci...
```

`KeyboardButtonUrl` даёт готовый URL. `KeyboardButtonCallback` (с `data=`) URL не содержит —
его эффект заранее неизвестен и жать его нельзя (см. «Границы» в SKILL.md).

**`telegram-get-message-link` заодно выдаёт публичный username канала** — и он у каждого
канала свой. Не переноси username, полученный для одного `chat_id`, на сообщения другого:
`t.me/s/devs_it/941` молча отдаёт совсем другой пост с тем же номером, и фетч возвращает
«такой вакансии тут нет». Бери линк на каждое сообщение из его собственного чата.

## Кнопки и ссылку забирай в один проход

`telegram-get-message-buttons` и `telegram-get-message-link` дешевле вызвать сразу, пока
`chat_id` и `msg_id` уже на руках, а не возвращаться за ними вторым проходом. Часто именно
в кнопке лежит настоящий URL отклика, и без него ресёрч уходит не туда.

## ⛔ Греп по `Go|Golang` — это не чтение, но и не катастрофа

25.07.2026 я прогнал четыре больших телеграм-дампа (218 сообщений) грепом по `Go|Golang`,
а потом перечитал их целиком, чтобы проверить потери. Итог: **из шести вакансий, где Go
спрятан внутри текста, реально ценными оказались две — и обе греп всё-таки поймал**
(`Tech Lead/Solution Architect (Java / Go)` и `Senior PHP/GO Backend`, обе с Go в заголовке).

Что греп **не** поймал бы, будь он только по заголовкам: Staff Software Engineer с
«can work in Lua/**Go**/C as needed», Fullstack PHP/Angular с «**Go** for performance-critical
sections», System Analyst с «coding knowledge (Java, Kotlin, **Go**, or Python)». Все три
оказались нерелевантны — Go там вскользь.

**Вывод для практики:** греп по телу сообщения (а не по заголовку) даёт приемлемую
полноту на телеграм-каналах. Но проверять это надо хотя бы раз за скан, и лучше на самом
плотном источнике. Полная вычитка одного файла на 1700 строк подагентом занимает минуты —
это дешевле, чем потерять вакансию.

**А вот где греп ловит плохо** — там, где роль называется «Бэкенд-разработчик» без Go
в заголовке, а стек не перечислен в посте вовсе. Такие вылавливаются только открытием
вакансии, поэтому на площадках (не в телеге) фильтруй запросом площадки, а не своим грепом.

## Грабли, на которые наступил сборщик (26.07.2026)

Всё найдено живыми запросами при написании `scripts/scout`. Каждая из этих мелочей
тихо выбрасывала целый источник из прогона.

**hh.ru отвечает 406 на «неправильный» `Accept`.** Заголовок
`Accept: text/html,...,application/json;q=0.9` даёт `HTTP 406` на `/search/vacancy`:
content negotiation решает, что запросили не ту страницу. С `Accept` как у Chrome
(`text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,...`) — 200.
Симптом коварный: самый плотный источник просто исчезает из выдачи, а остальные работают.
`User-Agent` при этом достаточно любого браузерного.

**Стейт hh закодирован HTML-энтити.** Тег — `<template style="display:none"
id="HH-Lux-InitialState">`, а внутри `&#34;` вместо кавычек. Регулярка на
`<template id="...">` не совпадёт (есть атрибут `style` перед `id`), а содержимое надо
прогнать через `html.unescape` перед `json.loads`. Проверено: 82 вакансии в
`vacancySearchResult.vacancies` за 3 дня по `Golang`.

**Карточки Хабр Карьеры бывают с модификаторами класса.** Резать по
`'<div class="vacancy-card"'` нельзя: карточки вида
`<div class="vacancy-card vacancy-card--featured">` не совпадут, соседние куски слипнутся,
и чипы одной вакансии утекут в другую. Резать надо по границе слова
(`re.split(r'<div class="vacancy-card[\s"]', html)`). До фикса терялось 19 карточек из 51 —
то есть треть источника, молча.

**Чипы Хабра идут вперемешку:** грейд (`Senior`), формат (`Можно удалённо`) и города
в одном списке. Брать «первый кириллический чип» как локацию — значит записать в город
«Можно удалённо». Город это всё, что не грейд и не формат.

**У careered.io вилка разложена по полям, а не строкой:** `salary_from`, `salary_to`,
`salary_currency`, `salary_period` внутри массива `features` (пары `key`/`value`).
⚠️ **Ноль там означает «вилка не указана»**, а не «платят ноль» — записать 0 значит
показать в карточке «0–0 ₽» и соврать про условия. `links` у записи — пустой список,
не объект; ссылка собирается как `careered.io/jobs/<id>`.

**Двадцать ATS-досок последовательно — 47 секунд, параллельно — 4.** Это было самым
долгим местом всего сбора. Доски независимы, пул на 10 потоков решает.

**Полный опрос ATS-досок даёт 6 597 вакансий, из них под профиль ~1 100.** Остальное —
продажи, поддержка и маркетинг в других странах. Отсекать по названию роли нужно, но
**счёт отсеянного обязан быть виден**: «тихо потерял» и «отфильтровал» — разные вещи,
и через месяц никто не докажет, что доска отдала больше.

**Резолвер отклика едва не начал врать.** Первая версия тянула URL из встроенного JSON
по ключам `link` и `url` — и по вакансии Т-Банка на hh выдала «лучший путь: `setka.ru`»
(соцсеть из футера). Брать надо только «прикладные» ключи (`applyUrl`, `companySiteUrl`,
`hostedUrl`, `careers_url`, …) и держать денилист соцсетей с CDN. С этим правилом та же
страница даёт верный ответ: `l.tbank.ru/career_and_vacancies` → `tbank.ru/career/`.

**shadowhint без сессии редиректит на `/auth`** и отдаёт 27 КБ формы входа. Это хорошо:
источник виден как «нужен вход», а не притворяется нулём вакансий.

**Тело ошибки приходит сжатым — и из-за этого антибот-стена выглядит обычным 403.**
`urllib` не распаковывает тело `HTTPError` сам, поэтому маркеры искались в гzip-байтах
и не находились. Проверено на wantapply: до распаковки — «упал: HTTP 403», после —
«АНТИБОТ: just a moment» (Cloudflare). Распаковывать надо тем же кодом, что и успешный
ответ. Мелочь, из-за которой стена и поломка сливались в одно.

**Маркеры антибота ищи только в начале документа.** На полноценной странице выдачи
слово «captcha» встречается в тексте вакансии (кто-то ищет разработчика
антифрод-сервисов), и поиск по всему телу объявляет живой источник заблокированным.
Первых ~6 КБ достаточно: настоящая стена — это короткая страница, где маркер стоит
в самом верху. Проверено: hh (1 МБ выдачи) ложных срабатываний не даёт.

**Живые стены на 26.07.2026:** `wantapply.com` — Cloudflare «Just a moment»,
`avito.ru` — «Доступ ограничен: проблема с вашим IP». Обе распознаются и выводятся
статусом `АНТИБОТ`, прогон при этом доходит до конца и возвращает ноль.

## hh.ru — сам поиск, а не только бот

**Самая дорогая ошибка одного из сканов.** Я разобрал сообщения бота hh и всю историю
откликов — и ни разу не открыл поиск на самой площадке. Один запрос дал **86 вакансий
за трое суток**, из которых десятки не встречались ни в одном другом источнике,
включая позицию с вилкой 450–600K.

```
hh.ru/search/vacancy?text=Golang&area=113&order_by=publication_time&search_period=3&items_on_page=100
```

`area=113` — вся Россия, `area=1` — Москва. `search_period` — дни, отбирает
по публикации-или-обновлению.

**Данные бери из встроенного стейта, а не из вёрстки.** Селекторы вроде
`[data-qa="vacancy-serp__vacancy-date"]` отдают пустое, а в `<template id="HH-Lux-InitialState">`
лежит весь JSON с датами и вилками:

```js
const tpl = document.getElementById('HH-Lux-InitialState');
const st  = JSON.parse(tpl.content ? tpl.content.textContent : tpl.textContent);
st.vacancySearchResult.vacancies.map(v => ({
  id: v.vacancyId, name: v.name,
  company: v.company && v.company.visibleName,
  pub: v.publicationTime && v.publicationTime.$,     // ISO
  sal: v.compensation                                 // {from,to,currencyCode}
}));
```

`items_on_page=100` отдаёт все результаты одной страницей — пагинацию гонять не нужно.

**Один запрос `Golang` покрывает почти всё.** Проверено: `text=Go разработчик` вернул
98 позиций, но новых по существу — две, остальное шум от слова «разработчик».
Гонять десяток формулировок смысла нет.

## Боты — самый плотный источник, и вот как их читать

Проверено 25.07.2026: по количеству живых Go-вакансий с открытыми вилками **четыре бота
дали больше, чем все девятнадцать каналов вместе**. Каналы за те же три дня отдали
в основном перепечатки без контакта, QA, аналитиков и рекламу курсов.

**getmatch — еженедельный дайджест это золото.** Раз в неделю бот присылает подборку
из 15 позиций строкой «роль @ компания + вилка + формат». Компания названа всегда,
вилка — почти всегда. Один такой пост закрывает половину скана. Ищи сообщение,
начинающееся с «Собрали еженедельную подборку вакансий».

**Короткие ссылки бота hh.ru раскрываются двумя редиректами:**

```
my.hh.ru/b/<code>  →301→  hh.ru/vacancy/<id>?utm_…  →302→  lipetsk.hh.ru/vacancy/<id>
```

Второй редирект — это гео по IP (см. ниже). `WebFetch` цепочку сам не проходит, но отдаёт
целевой URL: забирай `<id>` и фетчи **сразу `lipetsk.hh.ru/vacancy/<id>`** — содержимое
то же самое, и это экономит два вызова на вакансию. Часть страниц отдаёт 403 любым
фетчерам — такие открывай браузером или честно пиши «раскрыть не удалось».

**Подтверждения откликов и статусы читай всегда.** Runello раскрывает настоящее название
компании (так «крупнейший сельскохозяйственный банк» подтвердился как РСХБ-Интех).
getmatch сам сообщает: что ушло в архив, по чему нет ответа и на что пришёл отказ
с формулировкой.

## ⚠️ Сверяй новую вакансию со списком отказов, прежде чем писать карточку

Реальный случай: бот-агрегатор прислал вакансию, которая по деньгам и профилю шла
прямо в топ-5. А несколькими днями раньше по **этой же вакансии** (та же компания, роль,
продукт) уже пришёл отказ, зафиксированный в прошлом отчёте. Карточка была бы
предложением откликнуться туда, откуда только что развернули.

В тот же день это повторилось второй раз и хуже: карточку я написал целиком, с письмом
и разбором фита, — а отказ по ней лежал в откликах на hh, куда я не заглянул.

Правило в двух частях:

1. **Прочитай `98-*`/`99-*` из предыдущего скана** — агрегаторы переприсылают одно и то же
   неделями и про отказы ничего не знают.
2. **Открой `my.hh.ru/applicant/negotiations` до написания карточек**, а не после
   (как это делать — в `session-restore.md`). Это единственный источник, где видно
   отказы, приглашения на интервью и то, на что пользователь уже откликался.
   Прошлый отчёт покрывает только то, что нашёл прошлый я; hh покрывает всё.

**Отказ от той же компании по другой команде — не блокер, а строчка в карточку.**
Встречалось вживую: компания отказала по одной Go-роли и через две недели пригласила
по другой, более высокой. Не хорони компанию по одному отказу, но и не молчи о нём.

## ⚠️ Агрегатор переименовывает вакансию и прячет продукт

getmatch дал «**Ведущий Go-разработчик (Инфраструктура)** @ VK» без названия продукта —
читается как ядровая инфраструктура VK. На собственном сайте VK та же вакансия (совпали
Saga, dead-letter, «триллионы сообщений», DDD, тот же список требований) называется
«Старший Go-разработчик в команду инфраструктуры **в VK AdBlogger**» — то есть
инфраструктура внутри рекламного продукта.

Похожее у MAGNIT TECH: заголовок «Платформенная команда», описание команды — «QA Platform»,
задачи — про промодвижок, слаг URL — `loyalty-balances`. Три разных ответа в одном тексте.

Вывод: **всегда сверяй карточку агрегатора с собственной страницей работодателя** и пиши
в карточке то, что на сайте компании. Если внутри вакансии противоречие — не выбирай
за пользователя, вынеси его как вопрос рекрутёру.

и вести туда правильно.

## wantapply: у карточки внизу лежит «Apply on corporate website»

Проверено 25.07.2026. wantapply не врёт про «90% позиций с прямыми контактами»: в самом
низу страницы вакансии есть ссылка **«Apply on corporate website»**, и она ведёт прямо
в ATS работодателя. Для Exness это оказался
`job-boards.eu.greenhouse.io/internalhiring/jobs/<id>` — то есть приоритет №1 из «Контакт
как можно ближе к работодателю», без всякого посредника.

Порядок: открыл карточку → пролистал до конца → забрал `Apply on corporate website` →
в карточку идёт **эта** ссылка, а не wantapply.

Там же внизу: дата публикации (`Published on: M/D/YYYY`), этапы найма («What your journey
looks like») и блок «See all N jobs at <company>».

**Нашёл ATS — опроси его целиком.** У Greenhouse доска отдаёт все вакансии компании одним
запросом, и рядом почти всегда обнаруживаются соседние позиции. У Exness так нашлись три
Go-роли вместо одной. Публичный board-token угадывается редко (у Exness он `internalhiring`,
а не `exness`) — **бери его из самой ссылки «Apply on corporate website»**, а не подбирай.

⚠️ wantapply стоит за Cloudflare: после перехода на страницу вакансии проверка может
подняться заново. Ждать, а **не проходить** — см. «Границы».

## Как раскопать спрятанный контакт

Ссылка почти всегда есть, но не текстом. По порядку:

1. **Инлайн-кнопка поста.** Слова «Откликнуться», «Подробнее», «Смотреть вакансию»
   в тексте почти всегда означают кнопку, чей URL при текстовой выгрузке теряется.
2. **Веб-версия поста:** `https://t.me/s/<канал>/<id>` — именно с `/s/`.
   Без него `t.me/<канал>/<id>` отдаёт только виджет без содержимого.
   Это же единственный способ достать URL, спрятанный под словом-гиперссылкой в тексте
   (у постов без инлайн-кнопок): так из поста Сбера вытащился `rabota.sber.ru/search/...`.
   Иногда `/s/` тоже отдаёт только виджет — тогда см. пункт 3.
3. **Первоисточник читается напрямую, без веб-фетча.** `telegram-read-messages` принимает
   `chatId` = публичный username канала, в котором ты не состоишь, вместе с
   `offsetId` = (нужный id + 1) и `limit: 2`. Это надёжнее и дешевле, чем фетчить
   `t.me/s/...`: там на одиночном сообщении часто приходит пустой виджет.
   Так из `hr_breakfast_emergency/99682` достался живой `@foreverinlovewithsummer`,
   а из `itfreelancers/5307` — `@ibrahim_marlen`.
4. **Цепочка агрегатора.** Пост вида `Contact: Доступно в источнике` (Dream Offer,
   Runello) → страница агрегатора → ссылка «Показать в источнике» / «Перейти к источнику»
   → первоисточник в другом канале, где контакт открыт текстом.
   Проверено: так находится живой `@username`. На агрегаторе не останавливайся.
   У Dream Offer источник лежит на `find.dreamoffer.app/vacancy.html?nn=<id>` и ссылается
   на конкретный пост `t.me/<канал>/<id>` — дальше сразу пункт 3.
5. **Агрегатор-витрина vseti.app** (кнопка «Описание вакансии» у постов Ostrovok, Яндекса)
   контакты не прячет и ведёт на официальные careers-страницы: `career.ostrovok.ru/vacancy/N`,
   `yandex.ru/jobs/vacancies/...`. Это сразу пункт (2) приоритета контактов — форма на сайте.
6. **Указана только площадка** (`Контакты: careered.io`, `career.habr.com`) — ищи
   конкретную страницу вакансии поиском по роли и компании.

Ссылки на сам телеграм-канал, `max.ru`, `vk.com`, `ok.ru` контактами не считаются.

## Payload в deep-link кнопки

У Runello наблюдался base64url-JSON: `eyJvcmRlciI6MTQ2MDQ2...` → `{"order":146046,
"action":"apply_vacancy"}`. Если payload декодировался и `action` про отклик — эта ссылка
открывает бота **сразу в режиме отклика**, что стоит вынести как «отклик в один клик».
У других ботов формат может быть иным или не base64: не декодировалось — отдавай `url=`
как есть, без обещаний, куда он ведёт.

## Ссылки с готовым письмом ломаются тихо

`mailto:` и `t.me/share` несут письмо в query-параметре, и многострочный кириллический
текст надо кодировать целиком. Ошибка здесь не падает, а молчит: ссылка открывается,
а тело письма пустое или обрезано на первом же `&`. Что стоит держать в голове:

- перевод строки, `&`, `?`, `#` и кавычки обязаны пережить кодирование —
  проверяй round-trip (раскодировал обратно и сравнил с оригиналом), а не глазами;
- у `mailto:` есть практический потолок длины: Outlook рвёт около 2000 символов,
  часть клиентов и прокси — раньше. Письмо на 120–200 слов проходит, но впритык,
  поэтому его полный текст всё равно должен быть в карточке;
- `t.me/share` открывает **выбор чата** с вписанным текстом — адресата выбирает человек.
  Прямой ссылки «написать конкретному @username с готовым текстом» в Telegram нет,
  и обещать её в карточке нельзя.

Для этого уже есть `scripts/applylinks.py`: на вход JSON со списком
`{slug, email|null, subject, body, vacancy_url}`, на выход — `mailto:` и `t.me/share`
с проверенным round-trip'ом (падает, если параметр раскодировался не в то, что клали)
и с длиной каждой ссылки, чтобы упереться в потолок `mailto:` заметно, а не молча.
Проверен на 10 письмах с кириллицей, переводами строк и `&` в июле 2026.

## ⚠️ Подагенты делят с тобой ОДНУ браузерную панель

Проверено 25.07.2026. Запустил трёх фоновых агентов по площадкам — и панель тут же
заполнилась их вкладками (`tab-2` careered.io, `tab-3` career.habr.com, `tab-4` europa.eu).
Моя навигация уехала в чужую вкладку прямо посреди чтения страницы: я запросил один сайт,
а `javascript_tool` выполнился уже на другом origin.

Практика:

- **Не гоняй агентов по тем же сайтам, что открыл сам.** Раздели заранее: агентам —
  то, что читается фетчем; себе — авторизованное и JS-тяжёлое (hh, shadowhint, wantapply,
  geekjob, LinkedIn).
- **Работай с явным `tabId`.** `preview_start` возвращает свой `tabId` — передавай его
  в `navigate`, `get_page_text`, `javascript_tool`. Без этого попадёшь в активную вкладку,
  а активной её сделал агент.
- **Проверяй `tabs_context` перед выводами.** Пустая или неожиданная страница — сначала
  посмотри, на каком ты origin, и только потом делай вывод про сайт.
- Скратчпад тоже общий: агенты складывают туда свои дампы. Имена файлов не конфликтуют,
  но не удивляйся чужим.

## Браузерная панель: две ловушки

**`navigation ... denied or failed` — это две разные вещи.**

1. **Мёртвый `tabId`.** Вкладки исчезают сами (в июле 2026 `tab-9` пропал между вызовами),
   и навигация в несуществующую вкладку падает с тем же текстом, что и блокировка.
   Прежде чем делать выводы про сайт — `tabs_context` и убедись, что вкладка жива.
2. **Гейт на новый origin.** Панель требует одобрения пользователя на первую загрузку
   незнакомого домена. В одном заходе `hirehi.ru` открылся, а `geekjob.ru`,
   `hack-offer.tech` и `relocate.me` — нет, при том что curl отдаёт по ним 200.
   Это не «сайт закрыт», а «панель ждёт клика». Скажи пользователю, какие домены
   одобрить, — сам обойти нельзя и не нужно.

Ещё: `tabs_create` может вернуть ошибку «tab cap reached», но вкладку при этом создать
(так появился `tab-13`). Проверяй `tabs_context`, а не верь тексту ошибки.

## У агрегаторов есть открытые API — они дешевле и полнее браузера

Найдено 25.07.2026, экономит десятки вызовов и не требует логина:

| Площадка | Эндпоинт | Что отдаёт |
|---|---|---|
| **find.dreamoffer.app** | `find.dreamoffer.app/db/pg/read`, таблица `vacancies_ai_db` | все поля вакансии, **включая колонку `link` с прямой ссылкой на исходный пост `t.me/<канал>/<id>`** — то есть «Доступно в источнике» вскрывается сразу, без обхода цепочки |
| **careered.io** | `careered.io/api/jobs?offset=` | список вакансий, сортировка по дате, новые сверху. Снимает проблему SPA целиком |
| **hack-offer.tech** | SSR-JSON на странице (`payload.jobs`) + деталка `/vacancy/<slug>` | `source_channel`, `source_text`; `contact` и `apply_url` — `null` |

**Практика: сначала пробуй API, потом браузер.** careered.io раньше открывался только
рендером, а через `/api/jobs` читается обычным фетчем.

**hack-offer: отклик платный, но работодатель раскрыт.** На деталке стоит
`entitled:false` и плашка «Контакты и отклик — после вступления в клуб», а контакты
на странице принадлежат ООО «Я-Юниор» (`funnel@ijunior.ru`, `@ijuniorSupportBot`),
не работодателю. **При этом название компании и `source_channel` видны** — по ним отклик
делается напрямую и бесплатно, минуя клуб. То есть площадка полезна как источник
раскрытия, а не как канал отклика.

**careered.io: контакт за БЕСПЛАТНОЙ регистрацией.** Кнопка «показать» открывает модалку
регистрации, а не оплату. В отчёте так и писать — «контакт за бесплатной регистрацией»,
а не «платный посредник».

## Агрегатор показывает вакансию, но не контакт

Отдельно от авторизации: у большинства агрегаторов контакта работодателя **нет вообще**,
и вход тут ничего не меняет — они держат отклик внутри себя. Проверено на hirehi.ru:
вакансия читается анонимно и целиком, а в тексте ни телеграма, ни почты — только своя
кнопка «Откликнуться». Так же устроены Dream Offer («Контакт: доступно в источнике»),
Runello и careered.io.

Практический вывод: у агрегатора бери **название работодателя**, а контакт ищи у него
самого. Тот же пример: вакансия на hirehi оказалась сберовской — значит настоящий путь
это `rabota.sber.ru`, а не кнопка агрегатора.

## Как найти собственный канал найма работодателя

Цель — не «какой-нибудь контакт», а тот, что ближе всего к нанимателю (приоритет в SKILL.md).
Что сработало в июле 2026:

1. **Careers-страница на домене компании.** Угадывается по шаблонам: `<company>/careers`,
   `career.<company>`, `rabota.<company>`, `<company>/vacancies`. Проверено: `okko.tv/careers`,
   `career.ostrovok.ru`, `rabota.sber.ru` — все существуют и принимают отклик формой.
   Поиск «"работа в <компания>" вакансии официальный сайт hr» находит её быстрее, чем
   обход сайта руками, и попутно вытаскивает **HR-почту** (так нашлась `hr-okko@okko.tv`).
2. **Собственная страница вакансии вместо агрегаторской.** Одна и та же вакансия часто
   лежит и у агрегатора, и на сайте компании. Пример: Яндекс WebRTC — `career.habr.com`
   отдаёт её же, но у Яндекса есть
   `yandex.ru/jobs/vacancies/razrabotchik-webrtcservisov-na-go-v-videoplatformu-12037`.
   Ищи `site:<домен компании> <название роли>`.
3. **Страница работодателя на hh.ru** (`hh.ru/employer/<id>`) — не сайт компании, но её
   собственный аккаунт, где она сама читает отклики. Лучше бота-перепечатки.
4. **Компания на Хабр Карьере** (`career.habr.com/companies/<slug>/vacancies`) — там же
   видно, есть ли у неё сейчас открытые вакансии вообще. У Evrone, например, на момент
   проверки было пусто, хотя в Telegram вакансия висела: признак, что пост перепечатан
   или вакансия закрыта.

Проверяй актуальность: getmatch и hh честно помечают архивные вакансии, а перепечатки
в каналах — нет. Архивная вакансия с хорошей вилкой — это не предложение, а ориентир
по деньгам, и в карточке это надо разделять.

## ⚠️ Ограничение по гражданству ≠ ограничение по резидентству

Самая важная развилка для вакансий «вне РФ». Готовность переехать снимает
**не всякое** ограничение:

- **«Located in Russia» / «remote from anywhere excluding Russia and Belarus»** —
  это про **место работы**. Переезд снимает. Вакансия подходит.
- **«located in _or are nationals of_ Russia»** — это про **гражданство**, обычно
  экспортный контроль. Переезд **НЕ снимает**. Проверено на Elastic (25.07.2026):
  клаузула стоит **во всех 204 вакансиях компании**, российский паспорт закрывает
  их целиком независимо от адреса.

**Читай формулировку дословно и помечай в карточке, какой это случай.** Ошибка в любую
сторону дорогая: в одну — выбросишь годную вакансию, в другую — отправишь человека
в воронку, где его отсеют на комплаенсе после трёх интервью.

**Но не раздувай проблему: Elastic — исключение, а не отраслевая норма.** Прогон
регулярным выражением на `nationals of / citizenship / export control / OFAC / sanction`
по **1 343 вакансиям** дал ноль клаузул по гражданству: ClickHouse (171), Datadog (418),
GitLab (187), MongoDB (401), CockroachDB (32), Chainguard (74), Temporal (60).
Плюс Grafana Labs 0 из 131, Nebius 0 из 335, Exness 0 из 26, Sezzle чисто.
У остальных барьер географический, и переезд его снимает.

Проверка целой доски одним прогоном стоит дёшево и снимает класс сомнений — делай её,
когда компания крупная и американская.

## Ищешь «страна + язык» — ищи кластерами, а не вакансиями

Приём, который дал лучший результат 25.07.2026. Вместо перебора вакансий ищи **компании,
которые системно нанимают в нужную страну**, и опрашивай их доску целиком.

Так нашёлся Sezzle: **14 вакансий с локацией «Türkiye, Remote», Golang в 115 из 171**
вакансии компании, вилки $2 800–12 500/мес gross USD. Одна компания закрыла турецкое
направление лучше, чем все агрегаторы вместе.

Обратная сторона: проверка соседей результата почти не дала — у Trendyol, iyzico,
Dream Games, Peak Games, Picus Security публичные доски есть, а Go-ролей ноль;
у GitLab (187 вакансий) единственная турецкая позиция — продажи.

⚠️ **Ловушка с токеном доски:** `boards-api.greenhouse.io/v1/boards/insider` — это
**Business Insider (медиа)**, а не турецкий useInsider. Сверяй, чья доска открылась,
по названию компании внутри ответа, а не по совпадению токена.

## Зарубежные вакансии: три вещи, которых не видно из выдачи

Проверено 25.07.2026 на десяти немецких вакансиях. Карточка агрегатора врёт по трём
параметрам сразу, и все три критичны:

1. **Язык.** Schwarz Digits и VIBE требуют **свободного немецкого** — в выдаче Glassdoor
   этого нет вообще, вскрывается только на самой вакансии. Для русскоязычного кандидата
   с английским B2 это жёсткий блокер, а не «плюсом».
2. **Виза и релокация.** Из десяти вакансий спонсорство прямо заявила **одна** (adjoe).
   Остальные молчат — то есть по умолчанию его нет. **Не пиши «релокация» в карточке,
   если это слово не стоит в самой вакансии.** А вот 100%-удалёнка часто ограничена
   списком стран (Recare: только Германия, Испания, Португалия, Италия, Польша, Франция,
   Австрия) — это тоже надо вычитывать.
3. **Реально ли это Go-вакансия.** У Raisin тег Go на Glassdoor стоял, а в описании ядро —
   .NET и SQL Server, Golang только в «nice to have exposure». Всегда открывай описание.

**Дата публикации в выдаче тоже врёт.** Recare висел с меткой «2d», а на ATS работодателя
стоит 17 июня — больше месяца разницы. Дату бери с careers-страницы, а не с агрегатора.

**ATS немецких компаний, встреченные вживую:** Recruitee (`careers.<company>.com/o/<slug>`),
Ashby (`jobs.ashbyhq.com/<company>/<uuid>`), Personio (`<company>.jobs.personio.de/job/<id>`),
JOIN (`join.com/companies/<company>/<id>-<slug>`), Greenhouse EU
(`job-boards.eu.greenhouse.io/<board>/jobs/<id>`), SAP SuccessFactors, ADP Workforce Now,
Phenom People. Все отдают вакансию анонимно и содержат форму отклика — это и есть
приоритет №1 по контакту.

## Где искать вакансию помимо поста

Официальный careers-сайт компании, hh.ru, career.habr.com, getmatch, LinkedIn Jobs,
Greenhouse/Lever/Workable (`job-boards.greenhouse.io/<company>`). Пост рекрутёра
в LinkedIn часто даёт имя и прямой контакт, когда компания в Telegram скрыта.

Это даёт то, чего в коротком посте нет: настоящее название компании (в TG сплошь
«крупный банк»), вилку, полный список требований, этапы найма.

## Известные поломки и ограничения

- **SPA-страницы.** careered.io и часть агрегаторов рендерятся через JS: обычный fetch
  отдаёт голое слово «Careered». Открывай браузером (`preview_start` с `url`, затем
  `get_page_text`), только на чтение. Пустой ответ фетча — не повод писать «вакансии нет».
  При этом `read_page` на careered.io возвращает `(empty page)` и `Viewport: 0x0`, и
  `resize_window` это не чинит — а `get_page_text` и `javascript_tool` работают.
  Значит: текст бери `get_page_text`, ссылки — коротким JS по `document.querySelectorAll('a')`.
- **Заглушка в `href` ничего не доказывает — проверяй нажатием.** На careered.io под
  кнопкой «показать» лежит `href="https://t.me/#"`, и по этому я один раз заключил, что
  контакт платный, и выбросил три хорошие вакансии. Неверно: нажатие открывает модалку
  «Войдите на сайт или **создайте бесплатный аккаунт**, чтобы увидеть контакты».
  Плейсхолдер означал лишь то, что адрес подставляется после авторизации.

  Кнопка **раскрытия контакта** — это чтение, её нажимать можно и нужно: ничего никуда
  не отправляется. Не путай с кнопкой отклика, которую жать нельзя.

  Правило: увидел заглушку или пустой `href` — нажми и посмотри, что произойдёт;
  вывод про платность делай по тому, что реально показали, а не по разметке.
- **`telegram-get-chat-folders`** возвращал `Connection closed`. Не строй на нём отбор
  чатов — бери `telegram-list-chats`.
- **Платные посредники.** careered.io и подобные могут просить регистрацию или деньги
  за контакт. Всегда ищи параллельно бесплатный прямой путь; если его нет — так и скажи,
  не выдавая платный за единственный.
- **Flood-wait.** Лимиты на этом аккаунте не замерялись. Пойдут ошибки вида `FLOOD_WAIT` —
  снижай параллельность и не повторяй запрос сразу.
- **Коннектор Telegram падает посреди скана.** 25.07.2026 сначала точечно
  (`The connector's server isn't responding` на одиночных вызовах, лечилось повтором),
  а в конце — целиком: десять параллельных `telegram-mark-as-read` упали разом, и следом
  перестал отвечать даже `telegram-status`. **Отмечай прочитанным не пачкой в десять
  вызовов, а по 2–3**, и делай это сразу после того, как чат дочитан, а не одним заходом
  в самом конце: иначе весь скан остаётся неотмеченным из-за падения на последнем шаге.
  Если коннектор всё же умер — скажи об этом в отчёте и предложи отметить позже,
  в браузер за тем же самым не ходи.
- **`telegram-search-messages` глобально (без `chatId`) падает** — `Tool execution failed`
  на трёх подряд запросах 25.07.2026. Ищи по конкретному чату или через
  `telegram-search-chats` по нику.
- **`telegram-mark-as-read` для ботов не принимает числовой id.** `telegram-list-chats`
  отдаёт `P getmatch: бот с IT-вакансиями (1185216597) [bot]`, но вызов с `1185216597`
  падает: `Could not find the input entity for {"userId":...,"className":"PeerUser"}`.
  **Передавай username без `@`**: `g_jobbot`, `hh_rabota_bot`, `habrcareer_bot`,
  `RunelloBot` — так работает. Каналы и группы числовым id отмечаются нормально.
- **Дайджесты.** Простыня на тридцать позиций, где одна релевантная строка теряется среди
  менеджерских. Их легко пропустить целиком — реальный случай: единственная Go-вакансия
  внутри списка из вакансий продактов и маркетологов.
- **Короткие посты — тоже вакансии.** «Senior Go Developer, remote, 400k, пишите @hr» —
  полноценная вакансия с прямым контактом. Отсев по длине текста такое теряет.
- **Дубли переписывают.** Один и тот же наниматель в разных каналах может выглядеть как
  длинный пост рекрутёра и как короткая карточка агрегатора — общих слов у них мало.
  Совпадение по тексту такую пару не ловит, а по смыслу это одна вакансия и один отклик.
  Сверяй по сути: компания, роль, стек, условия, контакт.
