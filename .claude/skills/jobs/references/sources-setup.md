- **`shadowhint.com` — работает после захода пользователя** (25.07.2026): ~37 970 вакансий
  из Telegram с полнотекстовым поиском и фильтрами. Закрывает главную слабость Telegram —

агрегаторы со скрытыми контактами), а браузерные и авторизованные (hh, shadowhint,
wantapply, geekjob, LinkedIn) делай сам — у подагентов нет доступа к залогиненному профилю.

## MCP, которые пользователь решил подключить (24.07.2026)

### 1. HeadHunter — [gmen1057/headhunter-mcp-server](https://github.com/gmen1057/headhunter-mcp-server)

**Установлен 24.07.2026** в `~/.claude/mcp-servers/headhunter-mcp-server`,
venv собран, зависимости стоят, `.env` создан из шаблона.

Код проверен перед установкой: сетевые обращения только на `api.hh.ru`
и `hh.ru/oauth/*`, ни `subprocess`, ни `eval`/`exec`, ни обфускации.
Зависимости: `mcp`, `httpx`, `pydantic`, `python-dotenv`.

**Осталось (делает пользователь):** зарегистрировать приложение на
**https://dev.hh.ru/admin** → Client ID, Client Secret, App Token; вписать их
в `.env` или в блок ниже; добавить блок в `mcpServers` файла `~/.claude.json`
и перезапустить Claude Code.

```json
    "headhunter": {
      "type": "stdio",
      "command": "/Users/matvey/.claude/mcp-servers/headhunter-mcp-server/venv/bin/python",
      "args": ["/Users/matvey/.claude/mcp-servers/headhunter-mcp-server/server.py"],
      "env": {
        "HH_CLIENT_ID": "...",
        "HH_CLIENT_SECRET": "...",
        "HH_APP_TOKEN": "...",
        "HH_REDIRECT_URI": "https://jorqen.link/oauth/callback"
      }
    }
```

Поиск вакансий работает на app-токене. OAuth (`examples/oauth_flow.py`) нужен только
для чтения резюме и истории откликов — `hh_get_negotiations` полезен, чтобы видеть
статусы уже отправленного.

Инструменты: `hh_search_vacancies`, `hh_get_vacancy`, `hh_get_employer`, `hh_get_similar`,
`hh_get_areas`, `hh_get_dictionaries`, `hh_get_resumes`, `hh_get_resume`,
`hh_get_negotiations`.

> ⛔ **`hh_apply_to_vacancy` не использовать никогда.** Отклик совершает только
> пользователь — «Границы» в SKILL.md. `hh_get_negotiations` читать можно и нужно:
> оттуда видно статусы уже отправленных откликов.

### 3. JobSync — трекер откликов со встроенным MCP

Self-hosted: резюме, матчинг вакансий, история откликов. Закрывает то, что сейчас
собирается руками по перепискам: висящие без ответа отклики, ответы рекрутёров,
отказы с формулировками.

### 4. SuperJob API

Ключ бесплатный, регистрация на `api.superjob.ru`. MCP не нашлось — под него пишется
скрипт в `scripts/`, эндпоинт `api.superjob.ru/2.0/vacancies/?keyword=...`,
ключ в заголовке `X-Api-App-Id`.

## Что чем закрывается — не дублируй

**Браузер нужен только там, где нет MCP.** Telegram и почта закрыты своими коннекторами:
не открывай `web.telegram.org` и `mail.google.com` вкладками и не заставляй пользователя
логиниться туда второй раз. Через MCP: читать Telegram, готовить черновики писем.
Через браузер: hh.ru, `yandex.ru/jobs`, careers-сайты, LinkedIn, Avito — то, куда MCP
не дотягивается.

**Коннектор отвалился — это не повод вести пользователя в браузер за тем же самым.**
В июле 2026 Telegram и Gmail MCP отпали посреди сессии, и я по инерции открыл для них
вкладки. Правильно — сказать, что коннектор недоступен, и подождать его возврата;
дублирующий вход в браузере пользователю не нужен.

## Авторизованные площадки через браузер (без MCP)

Выбранный пользователем путь 24.07.2026: **он логинится сам в браузерной панели
(`preview_start` + `navigate`), а скилл дальше пользуется этой сессией.** Ни токенов,
ни OAuth-приложений, ни ключей.

**Куки сохранять не нужно и не получится.** Проверено на hh.ru: из JS видны только
трекинговые (`hhuid`, `crypted_hhuid`, `_ym_uid`, `uxs_uid`, `iap.uid`) — настоящая
сессионная кука `httpOnly` и в `document.cookie` не попадает. Сессию держит сам профиль
браузера; выгружать её куда-либо не надо. **И не выгружай:** сессионная кука — это
предъявительский доступ к аккаунту, а репозиторий публичный.

**Проверка живости сессии** — перед сканом открой площадку и посмотри признак логина,
а не предполагай:

```js
!!document.querySelector('[data-qa="login"],a[href*="/account/login"]')  // true = НЕ залогинен
!!document.querySelector('[data-qa*="mainmenu_applicantProfile"]')       // true = залогинен
```

Сессия протухла — скажи об этом и попроси залогиниться заново, не тяни молча
неавторизованную выдачу.

**Профиль персистентный — проверено 24.07.2026.** Метка
`localStorage.__jorqen_persist_probe` пережила перезапуск панели вместе с сессией hh.ru.
Значит логиниться нужно один раз, а не в начале каждого скана. Панель при этом может
«потеряться» между вызовами (`Preview not found`) — просто подними её заново
через `preview_start`, сессия останется.

**Где какой статус авторизации (24.07.2026):**

| Площадка | Статус | Что нужно |
|---|---|---|
| **hh.ru** | ✅ залогинен | ничего, поиск работает |
| **rabota.sber.ru** | ✅ логин не нужен | «Откликнуться» доступна анонимно |
| **career.ostrovok.ru** | ✅ логин не нужен | форма на 8 полей прямо на странице |
| **yandex.ru/jobs** | ✅ описание читается анонимно | логин нужен только на «Войти и откликнуться» — это делает сам пользователь |
| **Telegram, почта** | — | через MCP, в браузер не ходить |

**⚠️ hh.ru определяет регион по IP.** В первом заходе открылся `lipetsk.hh.ru`, хотя
пользователь в Москве. Регион искажает выдачу — либо переключить его в интерфейсе,
либо явно ходить на `hh.ru/search/vacancy?area=1` (Москва) / `area=113` (вся Россия).
