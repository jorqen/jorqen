# scout — сборщик вакансий

Механическая часть поиска работы: обойти площадки, сложить в базу, показать дельту,
разобрать, куда ведёт кнопка «Откликнуться». Суждение — что подходит, кому писать,
каким текстом — остаётся модели (скилл `jobs`).

Зачем разделение. Раньше обход площадок делала модель целиком, и он упирался в контекст:
пятнадцать сайтов означали мегабайты HTML, поэтому скан обрывался на середине, а
пользователь получал неполный список, не зная об этом. Скрипт снимает механику — модель
получает таблицу на сотню строк вместо дампов и тратит контекст на то, ради чего она
и нужна.

**Только стандартная библиотека.** Ни одной внешней зависимости: скрипт должен одинаково
подниматься локально, в облачной рутине и на чужой машине. Playwright нужен
исключительно для входа на авторизованные площадки, и без него всё остальное работает.

## Команды

```bash
python3 -m scripts.scout collect --days 3        # обойти площадки, сложить в базу
python3 -m scripts.scout new --since 3d          # что появилось с прошлого раза
python3 -m scripts.scout coverage                # кто отработал в последнем прогоне
python3 -m scripts.scout resolve <url>           # куда на самом деле ведёт «Откликнуться»
python3 -m scripts.scout raw getmatch --out /tmp/gm.html   # площадки без парсера
python3 -m scripts.scout auth status|login|check           # сессии площадок
python3 -m scripts.scout mark hh 134907406 --state applied # зафиксировать решение
```

Полезные флаги `collect`: `--query`/`--also` (несколько формулировок — одна не покрывает
всё), `--area` (`113` вся РФ, `1` Москва), `--ru-only`, `--ats-all`, `--no-store`
(для облака), `--format json`.

## Что закрывает

| Источник | Как берётся | Что отдаёт |
|---|---|---|
| **hh.ru** | встроенный `HH-Lux-InitialState` | ~150 вакансий за 3 дня, с вилками и датами. Анонимно |
| **career.habr.com** | разбор карточек | ~50, вилки и грейд |
| **careered.io** | `/api/jobs` | ~100, вилки разложены по полям |
| **LinkedIn** | гостевой `seeMoreJobPostings` | ~85 по зарубежным регионам |
| **ATS-доски** | Greenhouse / Lever / Ashby / Recruitee | 20 досок, ~6 600 вакансий → ~1 100 под профиль |

Полный прогон — около 18 секунд.

**Чего сборщик не делает намеренно:** не отбирает по релевантности, не склеивает дубли,
не оценивает фит и никуда не откликается. Отбор регулярками и дедуп по похожести текста
уже пробовали — коэффициент Дайса давал 0.29 на паре, которая была одной вакансией
в двух формулировках. Это работа модели.

## Площадки без парсера

`getmatch`, `geekjob`, `hirehi`, `hackoffer`, `rabota`, `shadowhint`, `wantapply` —
берутся командой `raw`, разбираются глазами. Причина честная: у getmatch данные лежат
в RSC-пейлоаде Next.js, у geekjob — Vue-SPA. Парсер под них написать можно, но он
сломается молча, а молча теряющий вакансии скрипт хуже его отсутствия.

## Авторизация

```bash
python3 -m scripts.scout auth login hh     # откроется видимый браузер
python3 -m scripts.scout auth check        # живы ли сессии
```

Вход выполняет **пользователь** — руками, своим паролем, своим кодом из почты. Скрипт
в этот момент ничего не вводит; он только сохраняет `storage_state` в `.auth/<площадка>.json`
после того, как человек вошёл. Дальше обычный сборщик подставляет куки заголовком
`Cookie`, и браузер на каждый прогон поднимать не нужно.

`.auth/` лежит в `.gitignore` — репозиторий публичный, а сессионная кука это
предъявительский доступ к аккаунту. С машины эти файлы не уезжают: ни в git, ни в облачную
рутину, ни на сервер. Ровно поэтому облачный сборщик ходит только по анонимным источникам.

Требует `pip install playwright && playwright install chromium`. Без него сборщик
работает, просто без авторизованных площадок.

## Резолвер кнопки отклика

```bash
python3 -m scripts.scout resolve "https://hh.ru/vacancy/134907406"
# → Лучший путь [external]: https://l.tbank.ru/career_and_vacancies
#   → редирект на https://www.tbank.ru/career/
```

Отвечает на вопрос «куда на самом деле ведёт кнопка», **не нажимая её**: читает `href`,
`data-`атрибуты, встроенные JSON-стейты, проходит редиректы GET-запросами. Различает
путь в ATS работодателя, внешний домен, витрину, форму отправки (`⛔ НЕ НАЖИМАТЬ`)
и JS-обработчик без адреса.

Только GET и HEAD. Ни одного POST, ни одной отправки формы — отклик совершает
исключительно пользователь.

## Состояние

`.scout/scout.db` (SQLite, в `.gitignore`):

- `vacancy` — виденное, с `first_seen`/`last_seen`. Отсюда берётся дельта;
- `decision` — что решено по вакансии (`applied`, `rejected`, `shortlist`, …).
  Отдельной таблицей, чтобы пересборка выдачи не затирала решения;
- `run` / `run_source` — журнал прогонов. Существует ради одного вопроса: обошли ли всё.
  `collect` возвращает ненулевой код, если хоть одна площадка упала.

## Когда что-то сломалось

Площадки меняют вёрстку молча, поэтому у HTML-адаптеров есть порог правдоподобия:
страница отдалась, а карточек ноль и нет пометки «ничего не найдено» — адаптер **падает**,
а не возвращает пустой список. Пустой список выглядел бы как «вакансий нет», и это
самая дорогая из возможных ошибок.

Известные грабли записаны в `.claude/skills/jobs/references/field-notes.md` — там же
чинить и дополнять.
