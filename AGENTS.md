# jorqen — правила репозитория

**Что здесь лежит:** сайт-резюме — статика на GitHub Pages. Источник один,
`resume/resume.yaml`; генератор собирает из него `index.html`, `en/`, `ru/` и
шесть файлов выгрузок (PDF, DOCX, TXT на двух языках).

🔴 **Механика поиска работы уехала 29.08.2026** в отдельный репозиторий
`~/Projects/kadr` (решение владельца 19.08.2026: «всё, что к скиллу — в новый
репозиторий; старый только для резюме и сайта и инфы обо мне»). Здесь её нет и
не заводить: ни сборщика вакансий, ни базы, ни сессий площадок, ни скилла
разбора. Данные о человеке тот проект берёт из собственного профиля, а не из
этого репозитория, — связи между ними нет вовсе.

Проект **готов и стабилен**: новых подсистем не заводить, задача обычно звучит
как «поправить текст резюме» или «починить вёрстку выгрузки».

Язык проекта — русский: документация, комментарии, коммиты. Резюме двуязычное
(EN/RU), идентификаторы английские.

## Инварианты — не ломать

1. **Единый источник истины:** резюме и контакты — только `resume/resume.yaml`;
   `index.html`, `en/`, `ru/` и выгрузки генерируются и руками не правятся.
   Правка в собранном файле проживёт до следующей сборки.
2. **EN и RU совпадают** по смыслу и объёму во всех форматах; опыт — по дате
   начала; PDF и DOCX одинаковы.
3. **Репозиторий публичный.** Личное, чему нельзя лежать в открытом виде
   (телефон), кладётся в `resume/resume.local.yaml` — он в `.gitignore`,
   накладывается на источник до проверки схемой. Как включить — докстринг
   `load_data`.
4. **Не собралось — правки нет.** `scripts/build_resume_formats.sh` валидирует
   схему и падает на расхождении; красная сборка означает, что коммитить нечего.
5. **Гейт разбора выгрузок обязателен** при любой правке генератора, шаблона или
   текстов: `scripts/test_resume_ats.py` читает собранные файлы так же, как их
   прочитает ATS, и ловит то, чего не видно глазами (сироты плашек, склейку по
   дефису, пропавшие ключевые слова).
6. **Список тестов существует только на диске** — `scripts/run_tests.py` обходит
   каталог. Рукописный список расходится с диском всегда, вопрос лишь в сроке.

## Команды

```bash
scripts/build_resume_formats.sh            # сайт и выгрузки; + схема
.venv/bin/python -m scripts.run_tests      # все test_*.py с диска
.venv/bin/python -m scripts.run_tests ats  # один модуль по подстроке имени
~/.nvm/versions/node/v22.18.0/bin/pyright  # типы прод-кода (pyrightconfig.json)
make help                                  # то же короче
```

PDF читается в гейте через `pdftotext` из poppler — он **обязателен**
(`brew install poppler`). DOCX разбирается распаковкой `word/document.xml`.

## Карта кода

- `resume/resume.yaml` — источник; `resume/resume.schema.yaml` — его схема.
- `scripts/generate_resume_outputs.py` — генератор, шаблоны в `scripts/templates/`.
- `scripts/build_resume_formats.sh` — сборка целиком; тот же скрипт запускает
  `.github/workflows/build-resumes.yml`, поэтому расхождению взяться неоткуда.
- `scripts/test_resume_ats.py` — гейт разбора: собирает шесть файлов во временный
  каталог и читает их глазами ATS.
- `scripts/run_tests.py` — прогонщик: список модулей берётся обходом диска.
- `assets/` — стили, скрипты и медиа сайта.

## Оснастка

- `.claude/agents/worker.md` — рабочий агент на одну ограниченную задачу.
- `.claude/skills/better-*`, `interface-review` — скиллы интерфейса, вызывает их
  человек сам (`skillOverrides` в `.claude/settings.json`).
- Разрешённое и запрещённое — `allow`/`deny` там же; прозой не дублировать.
